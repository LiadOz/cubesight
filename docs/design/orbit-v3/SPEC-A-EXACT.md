## 0. Ambiguities and inter-frame disagreements (read first)

Where the frames disagree both values are recorded and the question is flagged; none was silently resolved.

1. **Timer is not one style.** Sizes / baselines per frame: A-01: 120px text-faint at y 790 ls -4; A-03: 168px text-primary at y 812 ls -4; A-04: 128px text-primary at y 846 ls -4; A-05: 124px text-primary at y 782 ls -4; A-07: 76px text-primary at y 640 ls -2; A-09 dev(40,28): 92px text-primary at y 520 ls -2.5; A-09 dev(470,28): 84px text-primary at y 520 ls -2.5; A-10: 124px text-primary at y 782 ls -4; A-11: 96px text-primary at y 790 ls -3; A-12 dev(40,28): 84px text-primary at y 520 ls -2.5; A-12 dev(470,28): 84px text-primary at y 520 ls -2.5. Is this a deliberate size-per-state ladder (to fit the layout above it) or drift? Implement per-frame as measured unless told otherwise.
2. **Header opacity per state** (the `<g opacity>` around wordmark, nav, status): A-01 1, A-02 0.3, A-02b 0.3, A-03 0.3, A-04 0.3, A-05 1, A-06 1, A-07 1, A-08 1, A-10 1, A-11 0.5. The values 1 / .3 / .5 are all present; .3 during scramble, inspection and solve, .5 during replay and 1 on idle/results/review/history/drill/past solve. Confirm the rule (is replay really .5, not .3?).
3. **Keycap-row y differs**: rect y per frame: A-01: 870; A-02: 866; A-02b: 866; A-03: 866; A-04: 866; A-05: 870; A-06: 866; A-07: 870; A-08: 870; A-09: -; A-10: 870; A-11: 870; A-12: -. 866 on the scramble/inspection/solve/review frames, 870 on idle/results/drill/replay/history (keycap label baselines 880 vs 884). One row or two positions?
4. **Nav layout follows the label length (derived, not stated in the SVG)**: the underline width of the active item is 8.4 px per character in every frame (A-01 x 198 w 42; A-02 x 198 w 42; A-02b x 198 w 42; A-03 x 198 w 42; A-04 x 198 w 42; A-05 x 198 w 42; A-06 x 198 w 42; A-07 x 503.2 w 58.8; A-08 x 268 w 50.4; A-10 x 503.2 w 58.8; A-11 x 503.2 w 58.8); and the gap from one nav label's x to the next is 8.4 px x characters + 28 px. So nav x positions are 198, 268, 346.4, 408, 503.2 and an implementation using real text measurement will not match to the pixel. Treat the recorded x values as the spec.
5. **Segment gap is not constant**: A-01 2.5, A-02 2, A-02b 2, A-04 2.5, A-05 2.5, A-06 4, A-08 2.4, A-09 2.5, A-10 2.5, A-11 2.5, A-12 2.5 deg. Stroke widths do not scale with ring radius either (phone r150 uses the same 3 / 5 / 6 / 8 as desktop r300). Should the phone ring have proportional strokes?
6. **Stage-label radius differs per frame**: A-01 320.29 (rms 0.24); A-04 322.29 (rms 0.23); A-05 323.82 (rms 4.73); A-09 dev 470 166.29 (rms 0.23); A-10 323.82 (rms 4.73); A-11 322.3 (rms 0.23); A-12 dev 40 166.29 (rms 0.23). A-05/A-10 additionally have a large residual because of the callout rows (pause, EO skip, detour) that push label blocks off the pure radial rule. Which is canonical? A-01 is the idle baseline; A-04 and A-11 are 2.0 px further out than A-01, A-05/A-10 3.5 px (with large scatter), and the phone is r150 + 16.29.
7. **Cube size relative to the ring is not constant**: desktop 430px = 0.478 of canvas height, 1.433 x ring radius; phone 236px = 0.28 of canvas height, 1.573 x ring radius; history 260px = 0.289 of canvas height, 1.368 x ring radius. The cube is centred on the ring in all three, but fills desktop and phone rings by different fractions.
8. **Phone frames are 900x900 sheets with two 390x844 devices**, not 390x844 canvases (see section 1). The briefing for this spec said 390x844; the files say otherwise. Content is clipped to the device with rx 46.
9. **"No footer" rule vs the drawn frames.** Every desktop frame draws a bottom-left keycap row (y 866/870 and 880/884) and a bottom-right text line (y 884; A-01 also 862). AGENTS.md says "no footer". Either these are part of the screen (the SVGs say yes) or the rule means something else. Flagging, not resolving.
10. **Label baseline offset**: text y is a baseline. The SVG itself places pill text at (centre y + size/3), and that rule reproduces the 330 radius for all 20 move labels, so size/3 is treated as the vertical-centre correction.
11. **Cross-check** (not a source): `docs/design/orbit-v3/_src/lib.mjs` generated these frames; its `shadeF .86`, `shadeR .72`, default gap 2.5 and skip 4 agree with the measured values above.
